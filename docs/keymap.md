# 按键设计与设置方法

预设文件：[`preset/keymap.json`](../preset/keymap.json)。映射采用 SayAll 1.9.21 偏好字段；`preset/apply.py` 会将其合并到已配对的 RC003 档案，不复制任何人的完整偏好文件。

## 为什么这样排

- 高频编辑动作放在方向、确定、返回：左右单击逐字移动、返回单击连续删除、确定单击按 Codex 默认方式发送。
- 同一类动作成对：上／下长按是撤销／重做，左／右长按是行首／行尾，返回单击／长按是删字／删词。
- 双击左、右、返回都关闭；连续点击这些键不会被误识别成另一种动作。音量键双击、长按也保持空置，因为 RC003 上长按音量的实体测试不稳定。
- TV 长按“打开 Codex”，避免 SayAll 1.9.21 的“聚焦输入框”动作在 SayAll 自己位于前台时卡住。

## 具体动作

| 键 | 单击 | 双击 | 长按 |
| --- | --- | --- | --- |
| 电源 | `⌘[`：浏览器／Codex 后退 | 系统媒体播放／暂停 | `⌘W`：关闭标签或窗口 |
| 上 | `↑` | 无 | `⌘Z`：撤销 |
| 下 | `↓` | 无 | `⌘⇧Z`：重做 |
| 左 | `←` | 禁用 | `⌘←`：行首 |
| 右 | `→` | 禁用 | `⌘→`：行尾 |
| 确定 | `Return` | `⌘A`：全选 | `⌘⇧Return`：Codex 中尝试切换本次跟进消息的排队／引导方式 |
| 返回 | `Delete` | 禁用 | `⌥Delete`：删词 |
| 主页 | 显示桌面 | 打开 Google Chrome | 打开 Codex |
| 菜单 | `⌘K` | `⌘C`：复制 | `⌘V`：粘贴 |
| 音量＋ | 向上滚动 | 禁用 | 禁用 |
| 音量－ | 向下滚动 | 禁用 | 禁用 |
| TV | `⌘Tab`：切换应用 | `⌃⇧M`：Codex 模型选择器 | 打开 Codex |
| 语音 | 按住说话，松开结束 | 不参与普通映射 | 不参与普通映射 |

`⌘K`、`⌃⇧M` 和 `⌘⇧Return` 是送给当前前台 App 的快捷键；在其他 App 中可能是别的功能或无动作。Codex 若配置 `followUpQueueMode = "queue"`，`⌘⇧Return` 按其版本应在正在回复时对单条跟进消息使用相反方式。**此映射已发出快捷键，但尚未完成真实“引导”验收**。普通确定键保留 `Return`，因此仍由 Codex 默认设置决定排队或发送。

SayAll 对双击、长按有识别时间；设置长按的键不会在按住时无限重复。逐字定位请连续单击左右键；到行首或行尾则长按。返回键双击禁用，因此可以连按删除多个字。

## 手动设置

若不使用脚本，可在 SayAll 的“按键”页选中已连接的 RC003，开启自定义按键功能，逐项按上表配置。`自定义快捷键` 在 GUI 中选择或录入组合键；“主页双击”选“打开自定义 APP”并指定 Chrome。不要设置“聚焦输入框”作为 TV 长按。完成后关闭 SayAll 设置窗口，使目标 App 保持前台，再按实体遥控器测试。

## 自动应用与回滚

从仓库根目录运行 `python3 preset/apply.py` 可只读显示目标档案索引及是否需要变更。完全退出 SayAll 后运行 `python3 preset/apply.py --apply`。脚本会在用户 Library 中备份完整旧偏好并验证写入结果；它不上传备份。若有多个 RC003 档案，显式给 `--profile-index`。

回滚时先退出 SayAll，执行 `defaults import com.hd838a.RemoteMic '<本机备份路径>'`，再启动 SayAll。恢复的是该 Mac 的完整旧偏好，不能拿别人的备份导入。
